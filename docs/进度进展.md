## 2. 信息采集和数据清洗

- 供应端和生产端分别使用结构化采集表，必填项、选填项、重复明细、附件和声明字段分别处理。
- 草稿保存只做字段校验和持久化，不执行路线分析、工艺分析或报告研究。
- 用户点击“正式提交”后，系统才启动数据清洗、路线决策、工艺方案和本地资料扩充。
- 清洗过程会统一批次号、日期、数量、糖度、酸度、水分等字段格式，并识别空值、异常值和无效信息。
- 决策字段采用加权评分。产地、品种、批次号、数量、糖度、安全检测等字段权重不同，系统据此计算数据质量分和决策可用性。
- 无效字段不会直接参与路线评分；缺失的重要字段会进入待补充和人工复核清单。
- 原始填报内容仍保留，清洗结果作为后续自动决策使用的数据层，避免覆盖用户原始记录。

## 3. 任务和批次绑定

- 一条采集记录第一次正式提交时生成固定 `task_id`。
- 同一批次后续修改、保存、重新提交时继续使用原来的 `task_id`，不会因为修改次数变化而生成新任务。
- `record_id` 标识具体采集记录，`revision` 只记录这是第几次修改。
- 当前任务上下文统一使用 `task_id + record_id + revision`。
- 页面刷新、切换到路线决策、工艺方案或报告页面、返回采集页面时，系统会恢复当前批次上下文。
- 已提交记录修改为草稿后，系统保留任务身份，但不会提前重新分析；再次正式提交后才按新版本重新计算。
- 不同用户和项目的记录、任务上下文及报告结果按服务端作用域隔离，切换作用域时会清除旧上下文，避免串批次。

## 4. 路线决策和工艺方案

- 路线决策和工艺方案已经从问答操作改为工作台自动功能。
- 正式提交后，系统根据清洗后的有效字段对候选路线排序，输出首选、备选和观察路线。
- 每条路线包含评分、支持理由、限制条件和建议工艺阶段。
- 推荐路线会自动形成基础工艺方案，包括原料验收、分选清洗、核心加工、稳定处理、包装、储藏和副产物处理等阶段。
- 资料不足时，系统会将结果标记为“待补资料/小试复核”，不会把建议参数直接写成企业生产标准。

## 5. 右侧任务助手

- 右侧区域已经调整为当前页面的通用大模型助手，不再要求用户把已填写的采集信息重新输入一遍。
- 助手读取当前 `task_id + record_id` 对应的任务上下文，可以理解用户正在处理的批次和当前页面。
- 用户在右侧发送问题后，回答继续显示在右侧栏，不跳转到原来的独立 Agent 页面。
- 页面刷新和切换后，会话仍与当前任务绑定。
- 路线决策和工艺方案由工作台自动完成，右侧助手主要承担解释、检查、改写、补充说明和连续问答，不重复启动整套业务流程。
- 已完成右侧栏布局、输入区、对话区域和任务上下文恢复方面的交互修正。

## 6. 报告系统

### 6.1 生成条件

- 当前只提供一种报告类型：项目报告。
- 每份报告暂时只使用一条正式提交的采集记录。
- 草稿记录不能生成报告；点击生成时，服务端会重新检查记录状态和访问权限。
- 报告使用服务端保存的记录，不直接相信浏览器传来的批次数据，避免页面数据被修改后生成错误报告。

### 6.2 报告输入

报告会自动汇总以下信息：

- 主体名称、产地、品种、批次号、采收时间和批次数量；
- 糖度、酸度、水分、等级、检测资料和附件状态；
- 目标产品、数据质量分、推荐路线和工艺阶段；
- 使用单位、承办部门、经办人员、项目名称、统计区域、报告周期和工作目的；
- 本地文献检索结果、互联网检索结果和待人工复核项。

### 6.3 联网和本地资料检索

- 报告生成时会根据产地、品种、目标产品和区域自动组成研究问题。
- 检索内容包括当地种植面积和产量、品种特点、加工研究、市场需求、产业政策、质量安全和适用标准。
- 联网检索优先使用已配置的 Tavily；不可用时自动尝试 DuckDuckGo，再尝试 Bing RSS。
- 一个搜索来源失败后会继续使用下一个来源，不会因为单一搜索服务故障直接中止。
- 检索结果记录标题、网址、摘要、检索问题、检索时间和来源类型。
- 本地文献、互联网来源、用户提交事实和模型判断分别处理，不把搜索摘要直接当成已确认事实。

### 6.4 大模型撰写

- 报告会真正调用 DeepSeek 大模型重新撰写，不使用固定 HTML 或固定 Markdown 模板拼接正文。
- 大模型必须输出完整、连贯、正式的项目报告，不能只输出提纲。
- 当前要求报告包含18个主要章节：项目摘要、项目背景、建设必要性、原料与批次、产地与品种、市场、路线和工艺、建设内容、设备产能和场地、质量安全与合规、副产物利用、投资方向、运营与收益逻辑、实施计划、风险、结论、参考资料、待人工复核项。
- 外部重要结论需要使用来源编号；没有数据的投资额、收益率、市场规模和产能必须标记为“待补充”或“待测算”。
- 工艺参数只能写成小试建议或待验证条件，不能把单篇文献中的参数直接写成生产标准。
- 如果没有配置大模型密钥、接口调用失败或模型返回内容过短，系统会明确报错，不会用固定模板伪装成大模型报告。
- 上传的 Word 文件二进制、旧报告正文和旧来源不会进入大模型提示词，只发送本次项目需要的业务字段和证据摘要。

### 6.5 Word 模板和导出

- 报告中心只接受 `.docx` 模板。
- 浏览器会读取模板实际内容并传给服务端，不再只保存文件名。
- 服务端读取并保留模板的页面设置、页边距、标题样式、页眉和页脚。
- 支持项目名称、使用单位、承办部门、经办人员、统计区域、报告周期、工作目的和章节名称占位符。
- 模板中的占位符即使被 Word 拆分到多个文本片段中，也可以被识别和替换。
- 没有上传模板时，系统使用内置项目报告格式，生成封面、目录、分级标题、表格、页码和可点击来源链接。
- 最终结果只导出可编辑 Word，不再用 HTML 文件代替 Word。
- 报告页面可以预览大模型生成的标题、正文、列表、表格和来源链接。

## 9. 当前限制

- 报告服务当前作为 Python 模块运行在现有 Streamlit 应用内部，还没有拆成独立 HTTP 服务。
- 线上环境必须配置 `DEEPSEEK_API_KEY`，否则系统会提示未配置，不能生成大模型报告。
- 本机没有生产 DeepSeek 密钥，因此本机完成的是功能、接口、示例文档和测试验证，没有冒充完成真实付费接口调用。
- Streamlit Cloud 控制台需要登录，仓库中也没有保存公开网页地址，因此已经确认代码推送成功，但尚未从部署控制台确认线上构建结果。
- 知识图谱和外部业务数据库还没有接入，目前通过统一接口预留后续接入位置。
- 报告任务目前是同步执行，长报告生成期间页面需要等待；后续适合增加后台任务队列、进度查询、失败重试和历史版本管理。
- 云端生成的 Word 当前保存在运行容器中并同时返回浏览器下载；如果需要长期保存，需要接入对象存储或文档管理系统。
