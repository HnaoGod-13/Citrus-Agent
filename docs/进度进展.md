# 进度进展

## 信息采集与数据清洗

- 供应端和生产端使用不同的采集表，分别记录种植、投入品、原料品质、采收供应、原料接收、加工过程和成品质检信息。
- 必填项用于保证后续决策可以执行，选填项用于补充判断依据，不再要求所有人填写完全相同的内容。
- 保存草稿时只保存和检查信息；用户点击“正式提交”后，系统才开始清洗、分析和生成后续结果。
- 系统会统一批次号、日期、数量、糖度、酸度和水分等格式，识别缺失值、异常值和无效信息。
- 不同字段按照对决策的重要程度参与评分，形成数据质量结果和待补充清单。
- 用户原始填写内容会保留，清洗后的信息用于后续自动决策，避免覆盖原始记录。

## 路线决策和工艺方案

- 正式提交后，系统自动完成加工路线判断，不需要用户再到问答界面重复输入同一批信息。
- 系统会比较候选加工方向，给出首选、备选和观察路线，并说明推荐理由、限制条件和数据依据。
- 推荐路线会自动形成基础工艺方案，覆盖原料验收、分选清洗、核心加工、稳定处理、包装储藏和副产物处理等阶段。
- 信息不足时，系统会明确标记需要补充的检测、参数或小试内容，不会把建议直接当成正式生产标准。

## 任务助手

- 右侧区域已经改为当前任务的辅助大模型，可以理解用户正在处理的批次和当前页面。
- 同一批次修改、刷新、切换页面或返回后，仍然保持原来的任务关系和对话上下文。
- 用户可以直接在右侧询问缺失信息、决策原因、工艺风险、报告内容和修改建议，回答继续显示在右侧栏，不跳转到其他 Agent 页面。
- 路线决策和工艺方案由工作台自动执行，右侧助手主要负责解释、检查、补充和连续问答，避免重复执行同一流程。

## 报告撰写

- 当前统一生成项目报告，一份报告使用一条正式提交的采集记录。
- 报告会自动汇总主体、产地、品种、批次、数量、质量指标、检测资料、目标产品、路线决策和工艺方案。
- 用户只需补充使用单位、承办部门、经办人员、报告名称、区域、周期和项目目的等基本信息。
- 生成时自动查询本地资料和互联网资料，补充当地产业情况、品种特点、市场需求、加工研究、产业政策和质量安全信息。
- 报告由大模型根据批次事实和检索资料重新撰写，不再使用固定段落简单拼接。
- 报告内容覆盖项目摘要、项目背景、建设必要性、原料与批次、产地与品种、市场分析、路线和工艺、建设内容、设备与产能、质量安全、副产物利用、投资方向、运营逻辑、实施计划、风险、结论、参考资料和待复核项。
- 没有依据的投资额、收益率、市场规模、价格和产能不会被写成确定结论，而是标记为待补充、待询价或待测算。
- 外部资料保留来源，用户提交事实、外部证据、分析建议和待确认内容分别表达，方便后续审核。

## Word 模板和导出

- 用户可以直接上传单位自己的 `.docx` 模板，系统会读取模板内容，不再只记录模板文件名。
- 系统可以保留模板的页面设置、页边距、标题样式、页眉和页脚，并填入项目名称、单位、部门、人员、周期和报告章节。
- 没有上传模板时，系统使用统一的项目报告格式，生成封面、目录、分级标题、正文、表格、页码和参考资料。
- 最终结果导出为可编辑 Word，用户可以继续修改、审核、补充数据并形成正式版本。
- 报告页面支持预览标题、正文、列表、表格和来源链接。

## 完整示例效果

已经形成“广西南宁武鸣沃柑 NFC 果汁及副产物综合利用项目”完整示例。示例使用武鸣沃柑批次信息，自动汇总原料情况、产业资料、市场验证、加工路线、建设内容、设备需求、质量安全、副产物利用、投资方向、实施计划、风险、参考资料和人工复核事项，最终生成17页可编辑 Word 项目报告。
