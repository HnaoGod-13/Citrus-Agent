# 双端产业信息采集

入口：工作台 → 产业数据采集。供应端与生产端各有七个分步环节，共享字段字典 `app/intake_schema.py`，表单由 `intake.js` 渲染。

## 工作流

- 从空白记录开始，按环节添加字段和重复明细。
- 保存草稿：服务端保存字段与证据附件，返回编号、状态和版本。
- 检查完整度：定位未填项目；服务端提交还会校验日期、数量、工序引用和检测结论冲突。
- 提交记录：状态为 `submitted`（待复核），不等于质量审核通过或商业发布。
- 采集记录：按当前服务端访问身份恢复已保存的文档。
- 生产端原料接收可选择当前身份保存的供应记录；只带入来源事实，数量和验收结果由生产端填写。
- “用于业务报告”需要用户勾选报告使用选项，传入本份记录的摘要。报告摘要不混入演示供需匹配数量。

## 持久化和范围

`industry_intake.db` 位于 `CITRUS_MEMORY_DB_PATH` 同级目录。每份记录包含服务端确定的 user/project 范围，客户端不能指定或更改归属。使用 SQLite 事务与 revision 检查防止覆盖其他页面的新版本。记录列表不加载附件内容；打开单份记录时才读取完整内容。

记录及原件对普通访问者按范围隔离，不提供跨组织公开浏览或管理员后台。登录、组织、审批人权限仍在后续账号任务范围。本次的提交状态仅表示已收到数据。平台运营方须通过受控的服务端维护路径管理数据，不应公开数据库或绕过访问范围。

当前 Streamlit 部署若没有持久卷，容器重建可能丢失运行数据库；本功能不能承诺跨重建恢复。正式企业试点前需配置持久云数据库或受控持久卷，并确定定期备份及恢复策略。匿名访问恢复能力仍受现有访问令牌有效期影响。UI 提供 JSON 完整备份（含附件原件）与导入、HTML 采集表导出。不要将这些业务文件提交到 Git。

## 文件与限制

附件支持 PDF、PNG、JPEG。每个不超过3MB、每份记录最多8个、合计9MB。服务端检查扩展名、编码、文件头和尺寸并记录 SHA-256；这不代表对文件内容进行了杀毒或质量验证。单组最多60条明细，单访问身份最多100份记录，新建保存受总容量限制。当前没有附件内容解析、OCR 或自动真假鉴定。

## 字段与依据

必填标识表示提交业务表单的要求，不表示每个字段都是对所有主体普遍适用的法定义务。空字段不会用演示值填充。数据完整度不等于检测合格评分。数值保存会规范全角字符、空格和有效数字，检测结果保留“未检出”“<0.01”等表达。完整度和格式检查不会自动将记录加入真实交易池。

字典记录了2026-09-07复核的官方法规入口和版本，包括农产品质量安全法第27条的生产记录要求、食品安全法的进货及出厂记录要求，以及GB 14881—2025、GB 2760—2024、GB 2762—2025、GB 2763—2026。具体产品的检测项目、适用限值、工艺控制值由企业按适用标准填写，系统不预置通用杀菌或农药剂量。

## 验证

`tests/test_intake_store.py` 验证空白数据、数值和日期校验、许可与质量冲突、文件原件保存、权限隔离和版本冲突。`tests/test_intake_ui.mjs` 验证两端独立模型、批次带入边界、明细完整度、HTML转义和保存回执重放。浏览器验收使用项目 output 目录的独立测试数据库。
