# 柑橘产业链智能决策 Agent Demo

这是一个面向柑橘批次加工决策的 Streamlit Agent Demo。当前版本已经从“表单分析 + 大模型问答”重构为统一的对话式 Agent 工作台，并进一步整理为受控 Agent 架构：Planning、Tools、Memory 和固定质控护栏都在后端显式执行。用户在聊天框输入批次信息后，Agent 自动抽取字段、调用本地文献库、运行规则评分、检查质控风险，并在同一轮对话里输出结论、工具过程、文献证据和 Markdown 报告。

当前 Demo 不替代实验室检测、食品安全放行、标签审核、报价审批和人工复核。它的定位是帮助业务和质控人员形成可追溯、可复核的加工决策草稿。

## 当前 Agent 流程

```text
用户聊天输入 / 上传图片 / 补充外观描述
  -> Agent 判断是否需要调用工具
  -> 从文本中抽取批次字段
  -> 如有图片，调用 Qwen 视觉模型生成结构化外观描述
  -> 受控 Planning 生成必需执行步骤
  -> 分层 Memory 读取工作状态、增量摘要、相关长期记忆和相似样本
  -> 识别原料、目标产品、工艺、参数、规模、设备和质量目标
  -> 把加工问题拆成工艺路线、前处理、单元操作、参数、质量、包装、安全和副产物子问题
  -> 对每个子问题调用本地文献混合 RAG，优先材料与方法、结果和含单位数据的片段
  -> 结构化提取参数，按原料/方法/规模隔离，交叉验证并保留冲突
  -> 调用规则引擎进行加工路线评分
  -> 调用质控规则检查风险边界
  -> 生成 Markdown 决策报告
  -> 固定质控护栏检查必需工具、检测缺失和合规边界
  -> 调用 DeepSeek 将批次事实、规则评分和文献证据综合为完整主回答
  -> 在同一对话中展示结论、证据、工具轨迹和报告
```

示例输入：

```text
我有一批新会茶枝柑，糖度10.5，水分18%，客户是茶饮品牌，帮我按整果、果肉、果皮、种子和副产物拆开判断加工方向并出报告。
```

## 模型配置

DeepSeek 用于普通对话和工具调用后的自然语言总结；Qwen 视觉模型用于上传图片后的外观识别。API Key 不在网页上输入，而是从本地配置文件读取：

```python
# agent/llm_config.py
DEEPSEEK_API_KEY = "你的 DeepSeek API Key"
VISION_API_KEY = "你的 Qwen 视觉模型 API Key"
VISION_MODEL = "qwen-vl-max"
VISION_API_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
```

`VISION_MODEL` 必须填写支持 `image_url` 输入的视觉语言模型。如果你已经部署了自己的 OpenAI-compatible 视觉接口，请把 `VISION_API_URL` 和 `VISION_MODEL` 改成部署接口对应的值；同名环境变量会优先于 `agent/llm_config.py`。

当前文本模型固定为：

```text
deepseek-v4-pro
```

如果没有填写 DeepSeek API Key，本地文献检索、规则评分、风险检查和报告生成仍可运行，但不能生成 DeepSeek 总结或普通大模型问答。如果没有填写视觉模型 API Key，上传图片将无法自动识别，只能使用人工外观描述。

注意：如果项目会上传到 GitHub 或发给别人，不要提交真实 API Key。

## 页面使用方式

- 底部聊天框是主入口，直接输入批次信息或追问。
- 侧边栏支持 JPG、PNG、WebP、BMP、GIF、TIFF、HEIC/HEIF、AVIF、JPEG 2000、ICO 等常见图片格式；服务端会校验并转换为模型兼容的 JPEG，再调用 Qwen 视觉模型生成结构化外观描述。“外观描述”仍可作为人工补充。
- 上传图片后在聊天框提出本轮问题，图片会作为消息附件保留并优先进入视觉模型；若同时提供了足够的批次数据，视觉结果会继续进入加工评分、文献检索和报告工作流。
- 当输入包含“分析、加工、报告、批次、陈皮、柑橘、果肉、果皮、果胶、精油、糖度、水分、农残”等意图词时，Agent 会自动调用工具链。
- 工具调用结果会在同一轮对话里展示，可展开查看：
  - 工具调用过程
  - 加工评分与质控风险
  - 文献证据
  - 工艺参数证据
  - 报告草稿
- 批次分析的主回答会按“批次事实—文献证据—综合判断—完整流程—风险与行动”组织；文献判断使用 `[文献N]` 标注，末尾列出题名、年份、页码和 DOI/本地来源。
- 用户本轮问题会作为第一条检索分面；同时保留陈皮、橙汁、果胶、精油、种子和副产物等全链路检索，既优先回答当前问题，也避免遗漏重要替代路线。
- 每条助手回答下方可展开“本次回答依据与审计”，查看本轮使用的记忆、相似样本、文献、工艺参数记录、工具数量和运行 ID。
- 生成的报告会保存到 `outputs/reports/`；完整工具结果保存为同名 `.tools.json`，旧版审计摘要写入 `logs/audit.jsonl`，完整运行审计写入记忆数据库。

## 参数化加工知识链路

加工问答不再只返回“陈皮、果汁、精油”等方向。用户明确目标产品时，Agent 直接启动加工知识链路；目标不明确时，先做路线分级，再围绕首选路线补检索。完整数据流如下：

```text
用户问题和当前批次
  -> 确定原料/目标产品/单元操作/参数/规模/设备/质量目标
  -> 生成 8～12 个工艺子问题
  -> SQLite FTS 关键词召回 + 中英文概念扩展 + 稀疏语义重排
  -> 产品和柑橘主题硬过滤
  -> 材料与方法/结果章节、具体单位和参数密度加权
  -> 跨文献去重，每篇最多保留少量切片
  -> 从原文句子提取参数、单位、条件、规模、方法、质量影响和来源定位
  -> 按产品 + 原料 + 单元操作 + 参数 + 单位 + 规模 + 方法分组
  -> 一致性检查、冲突保留、可信度分级
  -> 参数化流程表 + 设备/替代设备 + 质量指标 + 风险 + 待补信息
  -> 将文献 ID 和参数 ID 写入审计
```

每条参数的基础结构为：

```json
{
  "product": "",
  "raw_material": "",
  "process_step": "",
  "parameter_name": "",
  "value": "",
  "unit": "",
  "range": "",
  "conditions": "",
  "scale": "lab|pilot|industrial|unknown",
  "effect_on_quality": "",
  "source_id": "",
  "source_location": "",
  "confidence": 0
}
```

实现遵守以下边界：

- 只有原文中同时出现数值、可识别单位、加工单元操作和来源定位时，才允许进入候选生产参数。
- pH 是无量纲参数；其他参数缺单位时会记录为低可信度证据，但明确禁止进入推荐范围。
- 不同产品、混合原料、热风/真空/冻干等不同方法，以及实验室/中试/工业规模分别分组，不直接合并。
- 两篇及以上独立文献在相近条件下结果一致时标为高可信度；单篇直接报告标为中可信度并要求小试；冲突、缺单位或条件差异大时标为低可信度。
- 冲突参数保留各文献原值和条件，不取平均；分析检测方法中的离心、温度或浓度不会自动当成生产参数。
- 工艺流程始终完整列出。某一步没有可靠数值时显示“现有知识库证据不足”，不会用模型常识补数值。

页面的“工艺参数证据”可查看结构化结果；报告中的参数表同时显示操作、范围、适用规模/方法、关键控制点和文献 ID。完整原文切片仍保存在文献数据库，只向 DeepSeek 注入少量参数摘要和相关片段。

### 加工检索配置

配置集中在 `agent/processing_config.py`，可用环境变量覆盖：

| 环境变量 | 默认值 | 用途 |
| --- | ---: | --- |
| `CITRUS_PROCESS_SUBQUERY_TOP_K` | `5` | 每个工艺子问题的候选证据数 |
| `CITRUS_PROCESS_EVIDENCE_TOP_K` | `24` | 最终加工证据上限 |
| `CITRUS_PROCESS_PARAMETER_LIMIT` | `64` | 每轮结构化参数记录上限 |
| `CITRUS_PROCESS_CONTEXT_EVIDENCE_LIMIT` | `12` | 注入文本模型的加工证据片段上限 |
| `CITRUS_PROCESS_CONTEXT_PARAMETER_LIMIT` | `24` | 注入文本模型的参数摘要上限 |
| `CITRUS_PROCESS_CONTEXT_TOKEN_LIMIT` | `2800` | 加工参数摘要与片段的总 token 近似预算 |

建议提问时提供品种、产地、成熟度、°Brix、可滴定酸/糖酸比、原料缺陷、目标产品、生产规模和可用设备。信息不足不会阻止生成完整候选流程，但会减少可推荐参数，并在“仍需补充的信息”中列明。

### 真实本地文献运行示例（节选）

输入：`赣南脐橙，适合怎样加工成果汁？`。本次实际使用当前 `literature.db` 运行，没有给模型补造数值。输出会先给出完整路线：

```text
原料验收 → 分选 → 清洗消毒 → 破碎/榨汁 → 护色 → 酶解/澄清
→ 过滤 → 糖酸调整 → 均质 → 脱气 → 杀菌 → 灌装包装 → 储藏
```

本次检索到的可回查参数候选包括：

| 步骤 | 文献直接报告 | 适用边界 | 证据 |
| --- | --- | --- | --- |
| 均质/高压处理 | 文献片段出现最高 `300 MPa` 的处理条件 | 原料为 `mandarin`，来源片段还包含其他压力条件；规模未标明，因此不能把 300 MPa 当作赣南脐橙工业推荐值 | `1d9f9239ff9b`，2020，第14页 |
| 热处理 | `68 °C、15 s` | 单篇 `mandarin juice` 研究直接报告；仅作为小试候选组合，中可信度 | `1d9f9239ff9b`，2020，第14页 |
| 冷等离子处理 | 暴露 `120 s` | 单篇 `mandarin juice` 对比研究；设备和规模未标明，不能与热处理参数混合 | `d7ac6c3a9cbe`，2025，第6页，DOI `10.3389/frfst.2025.1692060` |

酶解、澄清、清洗消毒、脱气、灌装和该脐橙批次的货架期没有在本轮证据中得到条件匹配且可直接采用的数值，所以真实输出显示“现有知识库证据不足”，并要求补充成熟度、°Brix、可滴定酸、pH、目标浊度、设备能力、包装和冷链条件后再检索或设计小试。这正是系统的预期行为：完整流程不缺步，但没有证据的数值保持空缺。

## 分层记忆系统

当前实现不修改模型权重，也没有更换 DeepSeek 或 Qwen。记忆由应用层 SQLite、结构化状态、摘要和检索完成：

1. 最近对话：按估算 token 而不是固定消息条数裁剪；当前问题始终单独保留，并优先保留最近用户消息、最近工具结果和上一轮回答。
2. 结构化工作记忆：每个会话保存目标、阶段、领域、实体、约束、决定、已完成/待办步骤、缺失输入、工具摘要和文件引用。更新按字段白名单校验，模型或调用方不能整体覆盖状态。
3. 对话摘要：超过阈值后只处理“旧摘要之后、最近窗口之前”的新增消息；目标、关键实体、约束和已确认决定使用保留预算，不重复总结全部历史。
4. 长期记忆：只保存明确要求记住的内容、稳定偏好、确认决定、实验参数、文件引用和高价值工具结果。检索综合语义词项、关键词、时间、重要性及用户/项目过滤，并在注入前去重和重排。
5. 历史样本：品种、产地、时间、成熟度、指标、目标、方案、结果、来源和可信度单独结构化存储；上传图片按用户/项目隔离保存哈希文件引用，新问题只注入少量相关案例。
6. 审计日志：记录原始输入、提示词版本、上下文构成、检索 ID、工具参数和摘要、模型原始输出、最终输出、状态更新、模型与错误。API Key、token 和密码字段会脱敏。

每次文本模型调用按以下顺序组装：

```text
系统提示词
＋ 用户/项目配置
＋ 结构化工作记忆
＋ 增量摘要
＋ 相关长期记忆
＋ 相关文献和相似历史样本
＋ token 受控的最近原始对话
＋ 当前用户输入
＋ 当前步骤必要的工具结果摘要
```

当前事实、历史案例、文献证据和模型推断在提示词中被明确分开；历史样本不能冒充当前样本检测结果。新确认信息与旧记忆冲突时，旧记录保留并标记为 `superseded`，不会静默覆盖。

未登录场景会在浏览器 URL 中生成匿名 `uid` 和会话 `sid`，刷新或同一地址重开后可恢复；不要把带 `uid` 的 URL 当作生产级身份认证。进程重启且磁盘仍在时 SQLite 会恢复会话。若部署平台在重启/重建容器时清空磁盘，应把 `CITRUS_MEMORY_DB_PATH` 指向持久卷；本版本没有为了这一点引入新的云数据库依赖。

`MemoryManager` 已提供 `delete_memory()` 和 `clear_session()`，便于后续增加用户侧删除/清空入口。运行时记忆数据库不应提交到 Git。

## 文献库构建

把 `.pdf` 或 `.json` 文献放入 `文献/` 的类别子目录后运行：

```powershell
.\.venv\Scripts\python.exe scripts\build_literature_chunks.py
```

构建脚本会递归扫描所有类别目录，并执行：

- 按文件名哈希识别跨类别重复文献，保留全部类别来源但只解析一份正文。
- 用 `pypdf` 抽取 PDF；加密 PDF 由 `cryptography` 支持，结构异常时由 PyMuPDF 备用解析。
- 识别摘要、引言、材料与方法、结果、讨论、结论等章节，按约 1,200 字符、180 字符重叠做页内切片。
- 去除重复页眉页脚并截断参考文献区；每个切片保留题名、类别、年份、DOI、章节和原始页码。
- 增量写入 `data/literature/literature.db`，未变化的文献不会重复解析；删除源文件后，下次完整构建会同步清理数据库记录。
- 对纯扫描件建立“题录（待 OCR）”记录，使其可被发现，但禁止 Agent 用题名推断正文结论。
- 把文献数、切片数、文本质量和错误写入 `data/literature/manifest.json`。

常用参数：

```powershell
# 默认 8 个解析进程，适合本项目当前文献规模
.\.venv\Scripts\python.exe scripts\build_literature_chunks.py --workers 8

# 仅用于排障的小规模构建
.\.venv\Scripts\python.exe scripts\build_literature_chunks.py --limit 10 --output-dir outputs\literature-smoke

# 如需把新版数据库额外导出为 JSONL
.\.venv\Scripts\python.exe scripts\build_literature_chunks.py --export-jsonl
```

当前默认检索入口是 `comprehensive_search_knowledge()`：

- SQLite FTS5 先对近 10 万个切片做快速全文召回，不再在每次提问时全库逐条计算。
- 中英文术语桥接、中文 n-gram、关键词、稀疏语义相似度、章节、类别、数值密度和元数据共同重排。
- 普通知识问答也会先检索文献，而不只在批次报告流程中使用 RAG。
- 批次分析按原料质量、整果、橙汁、陈皮、精油、果胶、种子、副产物八个分面分别检索，再跨文献去重，避免单一大类淹没其他路线。
- 提供给模型的证据带 `[文献N]` 编号、题名、年份、类别、章节、页码和 DOI/本地来源；提示词要求区分直接结论、推断和建议，并限制体外/动物研究外推。

目前数据库收录 1,899 篇去重文献、99,874 个章节化切片；原目录中的 2,078 个 PDF 含 179 个跨类别重复文件。3 篇纯扫描件已建立待 OCR 题录，其余文献均有可检索正文。

## 当前边界

- 已接入 Qwen 视觉模型做外观初筛，但图片识别只用于可见外观描述，不能替代检测报告和人工质控复核。
- DeepSeek 负责自然语言理解和总结，不替代规则评分、检测报告或人工审批。
- 文献依据来自本地文献切片，正式使用前应人工复核原文、页码、实验条件和适用边界。
- 农残、重金属、微生物、黄曲霉毒素等食品安全结论必须来自真实检测报告。
- 食品安全放行、标签标识、对外宣传、报价和客户承诺仍需企业质控、法规、法务或业务负责人确认。
- 暂不接 ERP、MES、WMS、CRM 等企业系统。
- 默认 SQLite 可在同一磁盘上的服务进程重启后恢复；无持久卷的容器重建/重新部署仍需外部持久存储。

## P0 / P1 修复版行为

- 同一对话按 token 预算保留最近原始消息，并结合工作记忆和增量摘要解析“它、这个品种、这个方案、上一个样本”等指代；新批次分析仍隔离无关旧批次，避免串批。
- “单独把文献给我”等省略式追问直接读取上一轮实际引用，不重新猜测文献。
- 普通文献问答与批次分析都连接本地 RAG；批次检索把本轮用户问题作为第一检索面，并保留跨类别覆盖。
- 路线排序综合批次规则、直接相关文献数量和数据完整度，用户界面只显示适配等级、文献支持与数据置信度，不显示伪精确百分制。
- 糖度、酸度、水分和重量经过符号与范围校验；异常输入不会覆盖已有有效值，并在回答中明确说明。
- 检测语义区分“未检出/没有超标”“尚未检测”“结果异常”和“已检测但未给结果”。
- 云端使用 `data/literature/package/` 中的分片压缩索引，首次启动自动校验并还原完整的 1,899 篇、99,874 切片数据库。
