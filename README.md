# 柑橘产业链智能决策与加工流程生成 Agent

面向柑橘原料批次的行业 Agent：在文献、规则和质控护栏约束下，先判断“适合做什么”，再生成“具体怎么加工”的完整流程草案，并保留可核验的证据与运行记录。

> 项目阶段：中期演示样机。当前输出用于专家复核、小试设计和生产评审，不替代实验室检测、企业 SOP、食品安全放行或授权人员审批。

## 项目定位

柑橘加工决策通常同时依赖原料指标、客户需求、设备条件、行业经验和分散的文献资料。本项目把这些信息组织成一条受控工作流，服务于“原料验收—加工立项—小试设计—生产评审”环节。

系统回答四个核心问题：

1. 这批原料适合加工成什么？
2. 为什么这样判断，有什么可回查依据？
3. 选定方向后，完整加工流程是什么？
4. 哪些参数、检测或风险仍需人工确认？

## 核心能力

- **批次理解与校验**：从自然语言中抽取产地、品种、重量、糖度、酸度、水分、检测状态、客户类型等字段，并拒绝异常值覆盖有效信息。
- **图片外观初筛**：通过视觉模型提取颜色、成熟度、损伤和疑似霉变等可见现象；图片结论不替代理化或安全检测。
- **全果路线决策**：比较整果、果肉、果皮、种子和副产物五大类、16 条候选加工路线。
- **完整加工流程生成**：对目标产品生成从原料验收、分选清洗、预处理、核心加工、分离稳定、过程质控到包装贮藏和副产物处置的端到端流程。
- **参数化工艺草案**：将温度、时间、压力、浓度、料液比等参数绑定到具体工序、原料、方法、设备、规模和原始文献片段。
- **可核验证据**：证据分为“直接证据”“仅供参考”“证据不足”；只有直接证据可参与路线加分或公开为参数候选。
- **质控与合规护栏**：强制检查检测缺失、异常结果、霉变、储藏和食品安全边界，避免把建议写成放行结论。
- **连续任务与审计**：保存当前任务状态、增量摘要、相关长期记忆、相似样本、工具调用和运行审计，支持同一批次连续追问。
- **业务工作台**：提供 Agent、工作台、知识库、分析和设置五个页面，集中查看会话、样本、文献、运行趋势和隐私控制。

## 页面说明

| 页面 | 主要用途 |
| --- | --- |
| Agent | 输入批次、上传图片、选择快速/深度检索并查看主回答、完整流程、证据和报告 |
| 工作台 | 查看当前身份范围内的会话、运行和样本摘要 |
| 知识库 | 浏览、筛选和检索本地文献目录 |
| 分析 | 查看运行量、完成状态和近期趋势 |
| 设置 | 查看模型与存储状态，导出个人数据、查看访问记录并删除当前会话或全部项目数据 |

## 受控工作流

系统不是让大模型自由决定是否执行关键检查。批次分析固定经过 9 个步骤：

```text
用户问题 / 批次数据 / 柑橘图片
                │
                ▼
1. 识别业务场景        2. 读取受控记忆
3. 识别加工意图        4. 检索知识依据
5. 提取加工参数        6. 评估加工路线
7. 检查质控风险        8. 生成完整报告
9. 执行固定护栏
                │
                ▼
路线建议 + 完整加工流程 + 参数证据 + 风险边界 + 后续行动
```

设计原则：**模型负责理解和表达，文献负责提供依据，规则负责稳定判断，护栏负责守住风险边界，人工负责最终确认。**

## 快速开始

### 环境要求

- Python 3.11 或更高版本
- Windows、macOS 或 Linux
- 访问 DeepSeek/Qwen 接口所需的网络和 API Key；没有 Key 时仍可运行本地检索、规则、质控和报告降级流程

### 安装

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

macOS/Linux 激活虚拟环境：

```bash
source .venv/bin/activate
```

### 配置模型

推荐通过环境变量或部署平台 Secrets 配置，不要提交真实密钥：

```powershell
$env:DEEPSEEK_API_KEY = "your-deepseek-key"
$env:VISION_API_KEY = "your-qwen-key"
$env:VISION_MODEL = "qwen-vl-max"
$env:VISION_API_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"
```

本地开发也可填写 `agent/llm_config.py` 中的空配置项，但该文件不得保存真实生产密钥后提交。

### 启动

```powershell
streamlit run app/main.py
```

默认访问地址：`http://localhost:8501`

## 使用示例

```text
我有一批新会茶枝柑，糖度 10.5 °Brix，水分 18%，客户是茶饮品牌。
请按整果、果肉、果皮、种子和副产物比较加工方向，并给出首选路线的完整加工流程和可核验参数。
```

建议尽量提供：品种、产地、成熟度、重量、糖度、可滴定酸或糖酸比、水分、缺陷、检测状态、目标产品、生产规模、设备能力、包装和冷链条件。信息不足时系统仍给出完整流程框架，但不会用模型常识补造参数。

## 文献与证据

### 数据规模

云端包清单 `data/literature/package/manifest.json` 当前记录：

- 文献记录：17,300 篇
- 证据片段：365,119 个
- 原始 SQLite 索引：约 2.53 GB
- 部署形式：10 个 Zstandard 分片，首次启动时校验并恢复到运行缓存

`data/literature/manifest.json` 是早期小规模构建记录，不代表当前云端完整索引规模。

### 检索模式

- **快速检索**：适合现场演示和常规问答，控制候选数量与响应时间。
- **深度检索**：扩大候选范围、补充相邻片段并提供完整检索统计，适合复杂工艺问题；耗时明显更长。

### 证据准入

| 等级 | 含义 | 能否进入路线评分 | 能否公开为工艺参数 |
| --- | --- | ---: | ---: |
| 直接证据 | 原文片段可定位，且直接报告匹配对象、工艺、参数或结果 | 是 | 满足参数校验后可以 |
| 仅供参考 | 有正文，但对象、工艺、条件或定位不足以直接支持当前结论 | 否 | 否 |
| 证据不足 | 仅题录、待 OCR、正文过短或来源无法核验 | 否 | 否 |

检索分数只用于排序，不能提升证据等级。参数还必须同时通过工序、原料、单位、方法、设备、规模和原始片段绑定检查；同篇文献的相邻片段不能替代参数所在片段。

## 数据与隐私

- 匿名访问使用 URL 中的短期 `ctx` 恢复令牌，默认 24 小时失效；服务端只保存令牌哈希。
- 匿名身份与已配置的认证身份隔离，登出后不会沿用认证会话。
- 设置页支持导出当前用户在本项目中的 JSON 数据、查看访问记录、删除当前会话或删除全部项目数据。
- 删除操作要求输入精确确认词；分析任务运行期间禁用删除；文件清理失败会明确提示。
- 导出内容不包含 API Key、恢复令牌或令牌哈希，绝对文件路径会转换为逻辑引用。
- `30/90/90` 天分别是会话、运行审计和访问记录的目标保存期；当前演示版未启用后台自动清理任务，用户可在设置页主动删除。
- 默认 SQLite 在同一磁盘上可跨进程重启恢复；无持久卷的云容器重建后仍可能丢失运行数据。

## 输出与审计

- `outputs/reports/`：批次 Markdown 报告和同名工具结果 JSON
- `logs/audit.jsonl`：兼容的轻量运行日志
- `data/memory/memory.db`：会话、工作记忆、长期记忆、样本、完整运行审计和隐私事件

运行数据、真实密钥和用户上传文件不应提交到 Git。

## 为什么响应时间较长

一次批次任务不是一次模型问答，而是“字段抽取—多分面检索—证据分级—参数校验—路线评分—完整流程—质控—报告—模型总结”的组合任务。深度检索还会扫描更多候选和相邻片段；云端首次启动需要恢复约 2.53 GB 文献索引。因此首次启动、深度检索和证据较多的复杂问题会更慢。现场演示优先使用快速检索，并先完成一次预热。

## 为什么接入 Agent 后模型显得更保守

独立聊天模型可以按通用知识自由回答；本 Agent 要接受本地证据、固定规则、上下文预算和食品安全护栏约束。弱证据数值会被隔离，缺检测时不能给放行结论，缺可靠参数时必须留空。这种“少猜、可核验”的行为会显得更保守，但属于行业场景的设计目标。若答案出现真正的理解下降，通常应排查意图路由、检索噪声、上下文截断、模型版本/参数和提示词冲突，而不是简单增加提示词长度。

## 能力边界

- 完整流程是供专家复核和小试使用的工艺草案，不是可直接投产的企业 SOP。
- 文献参数是带原始条件的候选值，正式采用前需核对原文、设备适配、工程放大和法规要求。
- 图片只支持可见外观初筛，不能判断农残、重金属、微生物或内部品质。
- 食品安全、标签、宣传、报价、客户承诺和生产放行仍由授权人员负责。
- 当前未正式接入企业 SOP、LIMS、ERP、MES、WMS 或 CRM。
- 项目尚未通过大规模企业批次、小试和生产结果证明生产级准确率。

## 开发约定

1. 业务规则、证据准入和食品安全边界必须由确定性代码实现，不能只写在提示词中。
2. 新增工艺参数时必须保留原始片段、来源定位、单位、工序和适用条件。
3. 新增产品路线时必须同时补充完整流程模板、允许工序、设备/替代设备和回归测试。
4. 修改共享工作流、记忆隔离或输出契约时，应运行全量测试。
5. 不提交 API Key、运行数据库、日志、报告和用户上传文件。

## 路线图

### 近期：可信与稳定

- 收口唯一发布版本并持续完善端到端回归测试。
- 建立专家标注集，量化证据相关率、路线 Top-3 认可率、完整流程覆盖率、错误参数率和重大风险漏报率。
- 继续进行 OCR、来源分级、去重和跨领域误召回治理。

### 中期：产业试点

- 围绕陈皮、NFC 果汁、果皮精油/果胶三类典型路线开展企业小试。
- 接入企业 SOP、检测报告、设备清单、客户规格和历史批次。
- 建立“Agent 建议—专家确认—小试—结果回填—偏差分析—规则校准”闭环。

### 后续：企业化

- 增加正式登录、角色权限、审批、版本和数据生命周期管理。
- 先只读接入 LIMS/批次系统，再评估 ERP/MES 双向联动。
- 将路线排序扩展为技术、质量、产率、能耗、成本和收益的综合决策。
